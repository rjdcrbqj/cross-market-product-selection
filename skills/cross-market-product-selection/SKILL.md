# 多产品跨市场选品与货源匹配

以可追溯证据为一个或多个目标产品建立独立短名单。适用于 Amazon 市场研究、1688 货源筛选和两端商品匹配；不把任何品类的外形、部件或价格写死。默认用中文交付，ASIN、SKU、URL、API、FBA、Sorftime、SerpApi 等技术标识保留原文。

## 不可妥协规则

1. 先确认外观与功能，并为每个目标产品取得实际参考图；一行一个目标产品，分配唯一`目标产品ID`，再分别编号外观、排除项和功能。
2. 每个目标产品的参考图/必需视图、检索词、Amazon同类均价、价格带、证据、去重、评分、排名和 Top-N 必须按`目标产品ID`隔离，不得串用。
3. 外观、功能、商品身份、价格允许范围和供应商资质是硬门槛，必须先于评分。
4. 外观和功能必须逐项核验。严格多视图模式的每个候选至少要有主图和关键结构/状态图，每张至少 240×240；每个外观编号的证据必须分别写明“候选可见事实、对标参考、关键差异”。标题、关键词或复制的模板句不得作为外观通过证据。
5. `亚马逊候选`、`1688候选`和`货源匹配`只允许严格合格或待核验；图片必须嵌入，候选行还必须同时有对应商品的主图链接和商品链接；已淘汰只能进入`淘汰记录`。
6. 嵌入图片必须是可解码、非全透明且具有可辨识尺寸的实际商品图片；缩略占位图不能通过校验。
7. 所有商品、主图、供应商和证据 URL 既要保留完整的有效 http/https 文本，也要成为单击即可打开且目标一致的 XLSX hyperlink。
8. 只对严格合格且销量、价格、评价证据完整的候选计算总评分；候选表和严格结果都必须通过独立重算。
9. 平台产品总评分固定为：销量标准分 × 40% + 价格相似分 × 40% + 评价标准分 × 20%；价格分只能引用该行`目标产品ID`对应的目标售价或目标成本，固定权重不可改写。
10. Amazon 候选价格下限为 max(该目标产品合格同类均价,目标售价×(1-允许偏差))，上限为目标售价×(1+允许偏差)；同类均价至少使用 5 个去重后合格样本重算。1688 使用目标成本×(1±允许偏差)的上下限；已知价格越界必须淘汰，不得留在待核验。
11. 不得凑 Top-N，不得用 0、1、编号、摘要、占位图或猜测填补缺失事实。

## 执行流程

### 1. 冻结任务书

在正式检索、付费查询或批量采集前，先建立`目标产品`表：一行一个目标产品，每行有唯一 ID，并分别冻结实际参考图、视觉对标模式、必需视图、外观/功能/排除编号、Amazon 目标售价及偏差、1688 目标成本及偏差、采购档位和目标 Top-N。多产品任务必须逐产品确认，不得以“同上”代替。

### 2. 规划并检索

按`目标产品ID`分别写检索矩阵：核心词、同义词、形态词、功能词、排除词、市场变体和发现路径。不得用上一产品的搜索词、参考图或证据直接通过下一产品。

### 3. 规范化与证据台账

每条价格样本、候选、配对、严格、待核验和淘汰记录都填写`目标产品ID`。只在同一 ID 内以 ASIN、1688 商品 ID、SKU 或规范 URL 去重；不同目标产品之间允许同一市场商品被分别评估。

### 4. 先资格、后三态

按商品主体、硬属性与合规、详情页身份和变体一致性、实际主图与目标外观及套装一致性、跨来源一致性的顺序判断。对每个候选逐项填写`外观逐项核验`和`功能逐项核验`：每个任务书编号都要有通过/失败结论及对应图片、详情页或规格证据。泛泛的“外观相似”“功能一致”不能通过严格门槛；“通过（主图明确不是目标结构）”“通过（详情页未提供该功能）”等结论与证据矛盾的写法也不得通过。联合模式的每个逐项结论必须同时指明 Amazon 与 1688 两侧证据。每项候选只能处于一种状态：

- **严格合格**：所有硬门槛均有可靠证据且通过；
- **待核验**：未发现明确失败，但至少一个硬门槛缺少或冲突的可靠证据；
- **已淘汰**：至少一个硬门槛已有可靠证据明确失败。

只有严格合格进入排序；待核验保留在对应候选表并同步进入`待核验`，写明缺失、冲突和下一步；已淘汰立即移出候选表，只进入`淘汰记录`并写明失败门槛与证据。门槛值以“通过/待核验/不通过”为受控结论；`不通过：……`、`不合格（……）`、`失败-……`等带原因的失败文本同样视为明确失败，不能留在候选表。

### 5. 评分、导出与审计

严格合格且销量、实际价格、评价星级证据完整且无冲突的候选，才在同一`目标产品ID`内按固定公式评分和排名。销量、实际价格或评价星级任一缺失或冲突时，转为待核验，不计算总评分并从严格结果移出。Amazon 先在`价格基准`表按目标 ID 保留至少 5 个去重后合格样本并重算算术均价；候选价低于该均价或目标价格带下限、或高于上限时淘汰。1688 已知价格越界同样淘汰；严格行还必须绑定 SKU、采购档位、MOQ 和阶梯价。

## 停止与交付

遇到登录、额度、计费或限流；付费查询范围未确认；硬门槛无法核验；主图与标题或属性冲突；身份或变体不稳定；或达到目标数量必须造数时，停止受影响路径并说明下一步。交付时报告要求数量与严格合格数量、未覆盖路径、缺失或冲突字段、已用付费调用和影响结论的限制。

## 最终自查

运行`scripts/validate_workbook.py`并确认没有问题后方可交付。确认固定九表完整；每个业务行的`目标产品ID`已定义；每个目标的参考图、价格样本、证据、去重、评分、排名和 Top-N 未与其他目标串用；严格多视图的主图/对比图及结构化差异证据齐全；已知价格越界项已淘汰；不凑数；所有 URL 可单击且链接目标与文本一致。
