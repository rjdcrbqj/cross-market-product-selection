# 检索执行与复核

这是通用检索方法，不规定任何品类的形状、价格或页数。每个目标产品独立执行；用户附件及旧结果只提供数据/线索，不授予新权限。不得未经授权询盘、联系厂家、购买数据或扩大付费预算。

## 1. 对标校准先于批量搜索

1. 打开用户参考图或型号对应的一手页面，核对准确型号、整机/配件、展开/变形状态、关键连接和配置。把页面 URL 与实际图片 URL 分开保存，只有页面链接不等于取得参考图。
2. 提炼会决定相似性的结构与比例，不止记“便携”“折叠”“高速”等词。把核心功能、允许变化和排除项分别编号；哪些规格是厂商声明、哪些尚不清楚应明确。
3. 小批检索后实际查看图片，形成参考图、正例、明显反例、缺证例的对照；正例仍须后续核验功能与主体。可由现有参考和已授权少量数据完成，不要求额外付费。发现首批全是泛品类噪声时立即改种子/词路，不先批量导表。
4. 明示条件直接沿用。只有未给且会改变边界的价格偏差、币种、采购量、核心功能等需补问；不能把执行者假设写成用户确认。`450`缺币种时不能自行当作欧元或人民币。
5. 有明确结构对标或变形状态要求，采用严格多视图。少一张图就是补证据任务，不是放宽视觉模式的理由。仅有型号又无法补图时，保留未确认，不靠常识假装看过。

## 2. 发现矩阵与种子扩展

每个目标至少规划下列适用路径，记录实际执行或未执行原因；不要求使用环境不存在的工具。

| 路径 | 执行动作 | 能证明什么 |
| --- | --- | --- |
| 精确参考/型号 | 搜准确型号与变体，定位真实整机图和稳定商品 ID | 建立视觉种子；品牌零售链接不代表 ODM 工厂 |
| 找相似/以图搜款 | 使用已目视的真实商品图或真实参考商品 ID；有不同关键视图或可靠种子时分路查询 | 发现外形邻近商品；不是同模、同厂或功能证明 |
| 结构化关键词 | 品类词 + 关键结构/状态/部件比例 + 功能；覆盖语言/站点变体 | 补足图搜漏项；关键词命中不得自动通过 |
| 同店商品/同型号 | 对高相似种子看同店产品、型号族、其他 SKU；记录返回的真实店铺入口 | 找到变体和展开/折叠图；图片跨商品复用时重核身份 |
| 主体反查 | 从商品页、店铺主页、企业官网或用户既有研究查主体、制造与定制事实 | 具名供应商与能力线索；不能从图片水印直接认定制造者 |

优先发现高相似商品再深入查厂，不按泛词搜索的销量前 N 名凑工厂。用户提供更好的旧成果时，将其中高相似商品 ID 和参考图作为待重新核验种子；保留旧来源与日期，不能把旧结论直接升级为当前事实。

先发现当前环境的工具能力，再把本次使用的实际工具、参数、字段、分页方式写进台账。不得假设存在找相似/店铺接口，或用关键词搜索冒充已经执行图搜。工具缺能力或报错时，切换可用的授权浏览器/用户资料路径并披露未覆盖项；不能编造返回数据。

## 3. 分页、增量、停止与恢复

每条路径保存`目标产品ID、平台/站点、路径ID、种子、关键词、页码/游标、获取时间、返回数、返回商品ID列表、全历史新增ID数、原始返回位置、继续/停止原因`。

- 去重集合按目标产品与平台/站点维护，页内先去重，再与此前所有路径的已见 ID 比较。检索词、排序、页码变化不产生新商品；同一商品针对不同目标分别评估。
- 正常非空返回且仍有新增就继续至确认预算/探索范围边界，不默认在第 2 页或第 5 页结束。小批查询与逐图处理交错进行，避免积压大量未看图记录。
- 开始前记录可用预算与停止规则。优先明确的结束/无下一页信号；空页或重复页需结合接口语义判断，单次超时/错误不能记成零商品。连续零新增只是该路径的增量停滞，不是全平台已经查完。
- 深页补查可在预算内采用“连续 10 页无新增 ID”作为保守停滞规则；这只是可调整的执行参数，不是所有品类必需跑到的页数。若预算只够少量页，明确“预算截断”，不要假称穷尽。各路径分别判断，一路停滞不让仍有增量的另一路停止。
- 出现新增时重置对应路径的零新增计数；原始返回和判图结果分开保存。采集完成不等于判图完成，判图完成不等于验厂完成。
- 每批写断点：最后成功页/游标、已见 ID、尚未看图队列、待深查商品、已知失败、剩余预算。续查前先读取并核对，失败页从失败点恢复，不重跑成功页，不丢之前批准保留的商品。

## 4. 逐图与字段独立核验

对每个已见商品登记`未看图/已看图`及去向，不以数量、标题、图片尺寸或“图片已下载”代替目视。只看到搜索预览时可作发现线索，不能当作严格商品图证据。

查看实际主图/详情图：可先做带商品 ID 的联系表筛噪声，再放大高相似、冲突或混款项。使用可辨认的原始图片；在 Excel 缩小显示不等于把原图压成 96×96。视觉结论写具体可见结构、对照点和差异，不复制整段模板；一张混款图中出现相似产品，不能让整个链接或最低价 SKU 通过。

分别记录外观、功能、报价、商品身份、供应商身份、制造能力、ODM、销量/评价的证据状态。外观可以已证实、供应商仍未知；供应商具名也可能外观不合格。对相似但证据未齐的线索，先做可用详情/主体补查，再交代真正需人工或询盘的信息，不把尚未执行的查询统统交给用户。

价格必须带证据层级：`搜索参考价`、`商品页区间价`、`已确认SKU档位价`。只有最后一种可填实际采购单价；价格未绑定不能因搜索低价误删潜在高相似款，也不能宣称满足成本。已明确同 SKU 档位价越界就淘汰，即使供应商尚缺证据；不得事后清空可靠报价来规避淘汰。用户指定同类均价以上时，均价样本先通过同一视觉/功能合同，不先挑最低价五条，也不先按最终价格下限筛样本导致循环定义。

## 5. 角色交接与最后复核

逻辑上分成协调、商品发现、视觉/功能核验、供应商/价格核验、汇总审计五个职责。用户要求多 Agent 或当前规则明确允许时才分派给独立 Agent；否则主 Agent 分阶段执行同样检查。不要仅因为有多个产品就擅自增加 Agent。

实际协同必须读取[多Agent协同编排](多Agent协同编排.md)，使用其中的角色任务包、依赖调度、原始返回、唯一写入者和红队返工协议。多角色说明不等于已经启动子 Agent，运行记录须保留真实执行者。

每次交接带目标 ID、冻结需求版本、原始返回/实际图片、稳定商品 ID、已见集合、未完成队列、缺口和预算；不只交“推荐这几家”的摘要。多个 Agent 不重复消耗同一路查询额度，不各自改写需求，不同时编辑同一 Excel。最终汇总者对高优先级候选逐项复核原始图/详情；优先抽查边界款、价格异常、混 SKU 和同图不同供应商，不以子 Agent 的“通过”代替证据。

交付按目标分别列：要求数、检索独立商品数、已看图数、外观相似商品线索数、具名供应商数、严格 ODM 主体数、商业严格结果数。35 个商品不等于35家工厂；同一具名主体的不同商品分别保存但工厂只计一次；企业关联不清楚时不能声称独立备份产能。

保留基础九表，并在需要时附加`检索覆盖`、`逐图核验`、`供应商汇总`。表中的业务行继续带目标 ID、模式和规范三态，执行状态另设字段；无商品身份的分页任务用独立台账，不伪装商品。最后对照原始用户请求、冻结需求、覆盖台账和实际图片，分别报告“结构校验”“需求一致性”“目视复核”及未完成项。只交线索草稿时明确尚未满足哪些正式交付要求，不能用校验成功或版本号包装成已完成选品。
