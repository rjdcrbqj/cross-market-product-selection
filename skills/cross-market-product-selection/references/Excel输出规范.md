# Excel输出规范

以 `assets/通用选品数据库模板.xlsx` 为起点（如存在），并保留工作簿结构。使用中文工作表、中文表头和中文状态；技术标识如 ASIN、SKU、URL 可保持原文。

## 工作表与状态

固定七表：任务说明、亚马逊候选、1688候选、货源匹配、严格结果、待核验、淘汰记录。七表只表示模板能力；实际模式必须读取任务说明中“模式”的确认值，且每个非空数据行的“模式”必须一致，绝不能因同时存在两侧表头推断为联合。两端联动使用全部七表；单平台模式仍保留七表结构和表名，不适用的候选或匹配表保持为空且结构有效，不新增替代表以免产生八表歧义。状态只能使用“严格合格”“待核验”“已淘汰”，并将三类记录分离：候选表不得出现已淘汰；`亚马逊候选`、`1688候选`、`货源匹配`只含严格合格或待核验；严格结果只含严格合格；待核验写明缺失或下一步；淘汰记录只写已验证失败门槛和来源。已淘汰记录必须从候选表移除，不能为了展示搜索数量继续混放。

## 表格、链接和排序

每个数据区建立可筛选表格；一行对应一个稳定商品、报价或匹配对。中文表头应覆盖稳定 ID、商品名称、商品链接、主图链接、证据来源、取得时间、原始值、标准值、外观逐项核验、功能逐项核验、硬门槛、状态、原因、各项评分和平台产品总评分。

商品链接、主图链接、供应商主页和证据链接必须同时满足两层要求：单元格保留**具有 host 的有效 http/https URL 文本**用于审计；导出的工作簿还必须建立与该文本目标一致的**XLSX hyperlink 对象**，使链接在 Excel 中**单击即可打开**。只有蓝色或下划线样式、只有 URL 文本、链接目标缺失、目标与显示 URL 不一致，均视为失败。不得把数字`0`/`1`、商品编号、图片 ID、搜索摘要或空字符串伪装成链接。

`记录/配对ID` 只是记录键：Amazon 另按站点 + ASIN + 稳定变体去重，1688 分别按商品身份与供应商主体去重，联合按两侧稳定身份组成配对键。拥有已确认最终评分的严格结果按总分降序并从 1 连续排名，同分依次比较销量得分、评价数量、价格得分、稳定商品/配对 ID。最后一项仅作纯确定性兜底，不是新评分权重。保留原始值与标准值，ID 以文本保存，避免科学计数法。

## 图片与公式

候选行必须嵌入对应商品的实际主图：`亚马逊候选`、`1688候选`和`货源匹配`中的每个严格合格或待核验行都必须在图片列嵌入图片，并在独立列保留主图链接；`严格结果`中的严格合格行必须将实际主图嵌入 Excel。每张实际主图必须与同一行的商品 ID、站点和变体一一对应，图片锚定同一行、保持比例和统一缩略尺寸。嵌入媒体必须可解码、至少 32×32 像素且不是全透明图；不得以生成图、透明/微小占位图、数字`0`/`1`、图片 ID 或链接文本代替要求嵌入的实际主图。联合模式需分别嵌入并审计 Amazon 侧与 1688 侧图片，使每侧图片各自对应同一行的稳定 ID、变体和主图链接。

严格合格行还必须填写`外观逐项核验`和`功能逐项核验`。前者逐项覆盖任务说明中的全部`外观N`与`排除N`并引用实际图片证据，后者逐项覆盖全部`功能N`与`禁用功能N`并引用详情页或规格证据；概括性说明、标题、关键词和与“通过”结论矛盾的证据不能替代逐项证据。联合模式每个编号都必须同时标明 Amazon 与 1688 两侧证据。

评分应保留可检查的原始值、标准分、固定权重、加权分和平台产品总分公式。销量公式只比较同模式、同来源、同周期（Amazon 还须同站点）的严格行；价格公式只能直接引用任务说明的目标售价或目标成本，并要求行内目标值与任务目标一致；评价公式拒绝越界星级。`亚马逊候选`、`1688候选`和`严格结果`中的严格合格行分别独立重算。空值按确认的缺失规则处理，公式不得静默把未知当作 0，也不得出现 `#REF!`、`#DIV/0!`、`#VALUE!` 或损坏的外部链接。联合模式必须分别呈现市场机会、供应能力和匹配质量及各自证据；任务说明未确认最终配对公式和三类权重时，最终配对得分与排名保持空白。

## 导出后检查

导出后运行 `scripts/validate_workbook.py`，并实际打开或渲染检查工作簿。确认固定七表及中文表头、可筛选表格、具有 host 的有效 http/https URL 文本和目标一致的 XLSX hyperlink 对象、候选与严格结果中的嵌入图片及主图链接、逐项核验、对应平台价格硬门槛重算、总分降序、三态分离、公式和空白值均符合要求；逐行检查孤立图片、跨行图片，以及筛选、隐藏或调整行高后图片仍与对应单元格绑定。模板不预设冻结窗格；数据、公式、图片和校验不受影响，可在 Excel 中手动冻结。若工作簿引擎无法保留嵌入图片或 hyperlink，受影响行不得留在可交付候选表，也不得标为严格合格。

自动校验时，任何非空数据行缺少规范三态或使用其他状态，必须报告 `STATUS_INVALID`；候选/匹配表出现已淘汰必须报告`CANDIDATE_REJECTED_ROW`；门槛出现`不通过：原因`等描述性失败必须报告`CANDIDATE_FAILED_GATE`；`严格结果`、`待核验`、`淘汰记录` 中的非空行若分别不是“严格合格”“待核验”“已淘汰”，必须报告 `STATUS_SHEET_MISMATCH`。候选图片缺失或图片无效、URL 无 hyperlink、逐项证据不完整、行内目标与任务目标不一致、候选评分伪造或严格价格超限均是不可交付问题。
