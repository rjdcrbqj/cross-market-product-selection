# Excel输出规范

以 `assets/通用选品数据库模板.xlsx` 为起点（如存在），并保留工作簿结构。使用中文工作表、中文表头和中文状态；技术标识如 ASIN、SKU、URL 可保持原文。

## 工作表与状态

新输出使用固定九表：任务说明、目标产品、价格基准、亚马逊候选、1688候选、货源匹配、严格结果、待核验、淘汰记录。`目标产品`一行一个产品合同；`价格基准`一行一个 Amazon 同类有效售价样本。九表只表示模板能力；实际模式必须读取任务说明中“模式”的确认值，且每个非空业务数据行的“模式”必须一致，绝不能因同时存在两侧表头推断为联合。单平台模式仍保留九表结构，不适用的数据表保持为空且结构有效。旧固定七表单产品工作簿仅保留兼容校验路径，不作为新输出模板。

状态只能使用“严格合格”“待核验”“已淘汰”，并将三类记录分离：候选表不得出现已淘汰；`亚马逊候选`、`1688候选`、`货源匹配`只含严格合格或待核验；严格结果只含严格合格；待核验写明缺失或下一步；淘汰记录只写已验证失败门槛和来源。已淘汰记录必须从候选表移除，不能为了展示搜索数量继续混放。

## 表格、链接和排序

每个数据区建立可筛选表格；一行对应一个稳定商品、报价、价格样本或匹配对。`目标产品`之外的每个非空业务数据行必须填写可回指且唯一存在的`目标产品ID`。中文表头应覆盖目标产品 ID、稳定 ID、商品名称、商品链接、主图链接、对比/结构图链接、证据来源、取得时间、原始值、标准值、外观逐项核验、功能逐项核验、硬门槛、状态、原因、各项评分和平台产品总评分。1688 严格结果还须覆盖 SKU、采购档位、MOQ 和对应档位价。

商品链接、主图链接、供应商主页和证据链接必须同时满足两层要求：单元格保留**具有 host 的有效 http/https URL 文本**用于审计；导出的工作簿还必须建立与该文本目标一致的**XLSX hyperlink 对象**，使链接在 Excel 中**单击即可打开**。只有蓝色或下划线样式、只有 URL 文本、链接目标缺失、目标与显示 URL 不一致，均视为失败。不得把数字`0`/`1`、商品编号、图片 ID、搜索摘要或空字符串伪装成链接。

`记录/配对ID` 只是记录键：Amazon 另按目标产品 ID + 站点 + ASIN + 稳定变体去重，1688 分别按目标产品 ID + 商品身份与目标产品 ID + 供应商主体去重，联合按目标产品 ID + 两侧稳定身份组成配对键。拥有已确认最终评分的严格结果在各`目标产品ID`内按总分降序并从 1 连续排名，同分依次比较销量得分、评价数量、价格得分、稳定商品/配对 ID。最后一项仅作纯确定性兜底，不是新评分权重。Top-N 与候选数量也逐目标产品统计。保留原始值与标准值，ID 以文本保存，避免科学计数法。

## 图片与公式

候选行必须嵌入对应商品的实际主图：`亚马逊候选`、`1688候选`和`货源匹配`中的每个严格合格或待核验行都必须在图片列嵌入图片，并在独立列保留主图链接；`严格结果`中的严格合格行必须将实际主图嵌入 Excel。每张实际主图必须与同一行的目标产品 ID、商品 ID、站点和变体一一对应，图片锚定同一行、保持比例和统一缩略尺寸。普通单图模式下嵌入媒体必须可解码、至少 32×32 像素且不是全透明图；不得以生成图、透明/微小占位图、数字`0`/`1`、图片 ID 或链接文本代替要求嵌入的实际主图。联合模式需分别嵌入并审计 Amazon 侧与 1688 侧图片，使每侧图片各自对应同一行的稳定 ID、变体和主图链接。

严格多视图模式下，候选与严格结果必须同时嵌入同一商品/变体的主图和对比/结构图，分别保留两个具有 host 的有效 URL 与目标一致的 hyperlink；两张图都不得小于 240×240 像素。严格外观逐项核验按编号写出`候选可见事实`、`对标参考`、`关键差异`和结论。同一目标产品下不同严格结果不得整段复制相同视觉证据。缺任一视图、图片过小、视图与商品错配或只写泛化结论时不得进入严格结果。

严格合格行还必须填写`外观逐项核验`和`功能逐项核验`。前者逐项覆盖任务说明中的全部`外观N`与`排除N`并引用实际图片证据，后者逐项覆盖全部`功能N`与`禁用功能N`并引用详情页或规格证据；概括性说明、标题、关键词和与“通过”结论矛盾的证据不能替代逐项证据。联合模式每个编号都必须同时标明 Amazon 与 1688 两侧证据。

评分应保留可检查的原始值、标准分、固定权重、加权分和平台产品总分公式。销量公式先按`目标产品ID`隔离，再只比较同模式、同来源、同周期（Amazon 还须同站点）的严格行；价格公式引用对应目标产品行的目标售价或目标成本，并要求行内目标值与目标产品一致；评价公式拒绝越界星级。`亚马逊候选`、`1688候选`和`严格结果`中的严格合格行分别独立重算。Amazon 价格基准必须由至少 5 个同目标产品、去重、同站点、同币种、同类有效样本重算均价，严格下限取该均价与目标售价允许下限的较高值；1688 采用目标成本的上下对称价格带。已知超限记录直接淘汰。空值按确认的缺失规则处理，公式不得静默把未知当作 0，也不得出现 `#REF!`、`#DIV/0!`、`#VALUE!` 或损坏的外部链接。联合模式必须分别呈现市场机会、供应能力和匹配质量及各自证据；任务说明未确认最终配对公式和三类权重时，最终配对得分与排名保持空白。

## 导出后检查

导出后运行 `scripts/validate_workbook.py`，并实际打开或渲染检查工作簿。确认固定九表及中文表头、逐行目标产品回指、可筛选表格、具有 host 的有效 http/https URL 文本和目标一致的 XLSX hyperlink 对象、候选与严格结果中的嵌入图片及图片链接、严格多视图尺寸与结构化证据、逐目标产品价格硬门槛重算、逐目标产品总分降序、三态分离、公式和空白值均符合要求；逐行检查孤立图片、跨行图片，以及筛选、隐藏或调整行高后图片仍与对应单元格绑定。模板不预设冻结窗格；数据、公式、图片和校验不受影响，可在 Excel 中手动冻结。若工作簿引擎无法保留嵌入图片或 hyperlink，受影响行不得留在可交付候选表，也不得标为严格合格。

自动校验时，任何非空数据行缺少规范三态或使用其他状态，必须报告 `STATUS_INVALID`；候选/匹配表出现已淘汰必须报告`CANDIDATE_REJECTED_ROW`；门槛出现`不通过：原因`等描述性失败必须报告`CANDIDATE_FAILED_GATE`；`严格结果`、`待核验`、`淘汰记录` 中的非空行若分别不是“严格合格”“待核验”“已淘汰”，必须报告 `STATUS_SHEET_MISMATCH`。目标产品 ID 缺失/不存在、价格基准样本不足、候选价格超限、严格多视图缺失或过小、结构化视觉证据不完整、视觉证据整段重复，以及 1688 严格结果未绑定 SKU/采购档位/MOQ/档位价，均是不可交付问题。
