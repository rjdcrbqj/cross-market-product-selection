# 协同运行清单格式

多 Agent 运行时由主协调者保存 `协同运行清单.json`，所有相对文件路径以该清单所在目录为根。它记录任务依赖与交付状态；实际商品、证据、分页、预算和断点仍在各工作包文件中保存，不挤进一个巨大 JSON。

先按[需求基线格式](需求基线格式.md)保存用户已给/已确认的 `requirements.json`。在首次分派前对该文件的原始字节计算 SHA256 并记入清单，供交接检查期间是否改变；指纹只证明字节一致，不能证明内容经过用户确认。用户真的改变需求时保存新需求文件与确认依据，使用新运行ID，重新核验受影响结果，不更新旧清单来消除差异。

## 更新与验收

- 每个包的状态为 `待执行 / 执行中 / 已完成 / 部分完成 / 受阻`。先验收原始返回、结构化文件和完成条件，再记已完成；工作包完成指约定范围已处理，不表示平台穷尽或找到了目标数量。
- 同时运行的包拥有互不重叠的写入路径与检索责任；可在包中加 `路径范围、预算份额、已用预算、断点文件、真实调用记录、尝试ID`。并发配额/付费预算由主协调者统一分配，不能每个包重复拥有全部预算。
- 多产品为每个目标添加包；最终复核包列出全部受审目标并直接或间接依赖所有专业包。输入引用精确版本/尝试文件，不用“最新结果”隐式选择。复核结果要能追溯到本次原始返回。
- 完整原始返回与结构化输出不能占同一路径，也不能与其他包重名。重新尝试时保留原文件，把新路径记入清单并保存历史清单；下游使用新版本时重新验收。
- 独立复核的结构化输出至少保存 `当前裁决`、`复核范围`、`问题` 和 `条件`；有条件通过时主协调者在清单补 `条件落实证据` 字符串列表，每项包含条件及对应解决记录位置。程序不能证明条件实际落实，须人工目视/主 Agent 验收。
- 单 Agent 降级仍保留复核职责包，但 `协作模式=单Agent`、`独立于首次研究=false`，执行者可相同；计划校验可以通过，正式多 Agent 合并验收不会通过，交付时注明采用主 Agent 自查。
- `--phase plan` 检查清单和冻结需求是否可用；`--phase merge` 还要求工作包全部完成、输出文件非空、复核门通过。仅有检索或线索任务时不要额外补造商品销量、工厂资格或表格来取得更高级别的交付状态。
