# 需求确认与评分

正式检索前完成全局任务说明和`目标产品`表；任何会改变产品身份、硬门槛、价格或范围的变更都追加进追加式决策日志，不改写历史。

多产品任务必须一行一个目标产品，每行分配唯一`目标产品ID`。参考图、必需视图、外观/功能/排除编号、目标售价、目标成本、允许偏差、币种、采购档位和 Top-N 都属于该 ID，不得用“同上”或一个共享条件覆盖全部产品。

## 目标产品确认表

| 字段 | 确认内容 |
| --- | --- |
| 任务模式与市场范围 | Amazon、1688 或两端联动；站点、区域、类目或使用场景 |
| 参考图片/链接 | 用户提供的目标产品实际图片、商品页或可核验参考；只有型号名时不得视为完成 |
| 视觉对标模式与必需视图 | 选择普通单图或严格多视图；后者至少按`视图1=…；视图2=…`冻结整体与关键结构/状态 |
| 外观必须特点 | 按`外观1=……；外观2=……`编号记录形态、结构、颜色、材质观感、套装构成等可观察要求 |
| 允许变化 | 可接受的尺寸、颜色、装饰、包装或配置变化 |
| 外观排除项 | 按`排除1=……`编号记录明确不接受的外观、部件、附件、结构或套装；没有则写“无” |
| 必须功能 | 按`功能1=……；功能2=……`编号记录必须由详情页规格或功能证据证明的能力 |
| 可选功能 | 有则加分或备注，但不作为硬门槛的能力 |
| 排除功能 | 按`禁用功能1=……`编号记录出现即不符合的能力、用途或配件；没有则写“无” |
| 目标售价 | Amazon 侧目标销售价格与适用币种 |
| 目标成本 | 1688 侧目标采购成本与适用币种 |
| 币种 | 各市场原始币种及是否允许换算 |
| 数量档位 | 单件、MOQ、采购批量或销量分层口径 |
| Amazon价格允许偏差 | Amazon 实际售价相对目标售价可接受的上下偏差、边界和例外 |
| 1688价格允许偏差 | 1688 对应数量档位价格相对目标成本可接受的上下偏差、边界和例外 |
| 销量周期 | 销量数据的周期、站点、时间点与来源 |
| 评价口径 | 平均星级、评价数或其他指标的来源与时间点 |
| 去重口径 | ASIN、1688 商品 ID、SKU、规范 URL 或已确认的变体规则 |

每个目标产品行还应注明目标严格合格数量和`用户确认状态=已确认`；全局任务说明保存付费查询上限、数据口径、输出位置和探索范围。每个产品的目标是“最多 N 个严格合格”，不足时允许少于 N 个。

编号后的清单是后续逐项核验的唯一基准，每个编号等号后必须有明确、可判断的内容。每个严格合格行的`外观逐项核验`必须逐项引用全部`外观N`与`排除N`，给出“通过”及对应实际主图/详情图证据；`功能逐项核验`必须逐项引用全部`功能N`与`禁用功能N`，给出“通过”及对应详情页/规格证据。结论不能与括号内证据矛盾，例如不能写“通过（主图不是目标结构）”或“通过（详情页未提供功能）”。联合模式中，每个编号的证据都要同时指出 Amazon 与 1688 两侧页面或图片。看不到关键结构、证据无法绑定同一商品和变体，或任一编号没有证据时，转入待核验；有可靠失败证据时转入已淘汰。

## 决策日志与硬门槛

每条决策记录时间、确认内容、来源和影响范围。后续指令仅在明确冲突时覆盖前序规则；不冲突时两者同时生效。按稳定商品 ID/配对 ID 保存商品级保留与排除决定、决定依据和时间，避免在清理或去重时静默丢失已确认项目。将每个硬门槛写成通过条件、明确失败条件、可接受证据和缺证据结果。标题或关键词不得作为外观通过证据；外观要求必须以绑定同一商品和变体的实际详情页主图/详情图逐项核验。缺证据或来源冲突为待核验，明确失败为已淘汰。

## 评分

只对严格合格且销量、实际价格、评价星级证据完整且无冲突的候选评分。销量、实际价格或评价星级任一缺失或冲突时，统一转为待核验，不计算总评分并从严格结果移出。使用 `scripts/scoring.py` 中的 `sales_scores`、`price_similarity_score`、`rating_score`、`total_score` 四个函数；原始值与每项标准分必须同时保留。

平台产品总评分固定为：销量标准分 × 40% + 价格相似分 × 40% + 评价标准分 × 20%。这三个权重不是默认值或可调参数；任务说明、工作簿公式与校验器都必须保持 0.4、0.4、0.2。该公式只计算 Amazon 或 1688 各自的平台产品分，不能命名为联合模式的最终匹配分。

- 销量标准分只由严格合格且原始评分字段完整的同组记录计算，销量越高分越高。每个比较组先按`目标产品ID`隔离；Amazon 比较组至少为“目标产品ID + 模式 + 站点 + 销量来源类型 + 销量统计周期”；1688 至少为“目标产品ID + 模式 + 销量来源类型 + 销量统计周期”。单记录组或组内销量全相等时为 100；待核验、已淘汰、其他目标产品和不同组记录不得污染 MIN/MAX。
- Amazon 的价格相似分只对比当前`目标产品ID`在`目标产品`表确认的目标售价；1688 的价格相似分只对比当前`目标产品ID`确认的目标采购成本。两端联动时分别按各自市场口径计算，不混用售价与成本；候选行或严格结果行中的目标值必须与对应目标产品一致，不能自行改写目标以提高价格分。
- 价格相似分基于 `MAX(0, 100 × (1 − |实际价格 − 目标价格| / 目标价格))`。由于使用绝对差值，目标价格上下相同偏差得到相同分数。价格允许偏差只作为硬门槛，不进入评分分母。
- 评价星级只接受 0 到任务书确认的平台满分；越界值必须报错，不能静默截断。评价口径未确认或数据缺失时保持待核验，不以 0 代替。

在评分前逐个`目标产品ID`确认销量比较集、目标价格、对应平台的价格允许偏差、评价口径和去重口径。Amazon 还须建立该目标产品的同类价格基准：至少 5 个位于任务确认市场范围内、去重、同币种、同类且有可追溯来源的有效样本，重算合格同类均价；严格价格下限取“合格同类均价”与“目标售价 × (1−允许偏差)”两者较高值，上限取“目标售价 × (1+允许偏差)”。1688 使用目标成本上下对称价格带，并绑定目标采购档位。严格合格行必须使用对应目标产品与原始实际价格重新计算价格差并验证价格范围；已知超出范围的记录直接淘汰，不能留在待核验，也不能只接受单元格里手填的“通过”。`亚马逊候选`和`1688候选`中的严格合格行也必须独立重算销量分、价格分、评价分与总评分，不能等到严格结果才检查。不要用销量、评分或数量覆盖外观、功能、身份、价格范围或供应商资质失败。
