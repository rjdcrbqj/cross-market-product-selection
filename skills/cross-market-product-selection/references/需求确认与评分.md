# 需求确认与评分

正式检索前完成任务书；任何会改变产品身份、硬门槛、价格或范围的变更都追加进追加式决策日志，不改写历史。

## 目标产品确认表

| 字段 | 确认内容 |
| --- | --- |
| 任务模式与市场范围 | Amazon、1688 或两端联动；站点、区域、类目或使用场景 |
| 参考图片/链接 | 用户提供的图片、商品页或可核验参考；注明用途 |
| 外观必须特点 | 形态、结构、颜色、材质观感、套装构成等可观察要求 |
| 允许变化 | 可接受的尺寸、颜色、装饰、包装或配置变化 |
| 外观排除项 | 明确不接受的老式外观、部件、附件、结构或套装 |
| 必须功能 | 必须由详情页规格或功能证据证明的能力 |
| 可选功能 | 有则加分或备注，但不作为硬门槛的能力 |
| 排除功能 | 出现即不符合的能力、用途或配件 |
| 目标售价 | Amazon 侧目标销售价格与适用币种 |
| 目标成本 | 1688 侧目标采购成本与适用币种 |
| 币种 | 各市场原始币种及是否允许换算 |
| 数量档位 | 单件、MOQ、采购批量或销量分层口径 |
| 价格允许偏差 | 目标价格可接受的上下偏差、边界和例外 |
| 销量周期 | 销量数据的周期、站点、时间点与来源 |
| 评价口径 | 平均星级、评价数或其他指标的来源与时间点 |

任务书还应注明目标严格合格数量、供应商资质、所需字段、缺失值处理、输出位置、付费查询上限和探索范围。目标是“最多 N 个严格合格”，严格合格不足时允许少于 N 个。

## 决策日志与硬门槛

每条决策记录时间、确认内容、来源和影响范围。后续指令仅在明确冲突时覆盖前序规则；不冲突时两者同时生效。按稳定商品 ID/配对 ID 保存商品级保留与排除决定、决定依据和时间，避免在清理或去重时静默丢失已确认项目。将每个硬门槛写成通过条件、明确失败条件、可接受证据和缺证据结果。标题关键词只能帮助发现候选，不能单独证明外观；外观要求以实际详情页主图核验。缺证据或来源冲突为待核验，明确失败为已淘汰。

## 评分

只对严格合格且销量、实际价格、评价星级证据完整且无冲突的候选评分。销量、实际价格或评价星级任一缺失或冲突时，统一转为待核验，不计算总评分并从严格结果移出。使用 `scripts/scoring.py` 中的 `sales_scores`、`price_similarity_score`、`rating_score`、`total_score` 四个函数；原始值与每项标准分必须同时保留。

总评分为：销量标准分 × 40% + 价格相似分 × 40% + 评价标准分 × 20%。

- 销量标准分由同一已确认比较集的销量计算，销量越高分越高。
- Amazon 的价格相似分对比目标售价；1688 的价格相似分对比目标采购成本。两端联动时分别按各自市场口径计算，不混用售价与成本。
- 价格相似分基于 `100 × (1 − |实际价格 − 目标价格| / 目标价格)`，最低为 0。由于使用绝对差值，目标价格上下相同偏差得到相同分数。
- 评价标准分按已确认平台满分换算；评价口径未确认或数据缺失时保持待核验，不以 0 代替。

在评分前确认销量比较集、目标价格、价格允许偏差、评价口径和去重口径。不要用销量、评分或数量覆盖外观、功能、身份、价格范围或供应商资质失败。
