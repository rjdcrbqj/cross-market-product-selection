# 多产品选品提示词模板

将方括号内容替换为本次任务的真实信息。产品 A、产品 B 是两个独立目标；需要更多产品时按同一结构继续添加。

如果不想填写完整表，可用以下开场，让 Agent 先从真实参考资料提炼需求；不要填写尚未确定的参数：

```text
$cross-market-product-selection
请做通用多产品选品，不把我的对标产品泛化成同一大类。
产品A：[名称、参考图片/链接、核心功能、目标售价及币种、目标成本及币种]。
产品B：[名称、参考图片/链接、核心功能、目标售价及币种、目标成本及币种]。
市场：[站点]；目标：[各产品分别需多少商品/厂家]；允许付费预算：[金额或不允许付费]。
先查看每款实际参考图和功能资料，给出独立外形/功能需求卡。只询问影响结论的缺项；不得自行扩大价格偏差、降低功能、切换视觉模式或假定采购量。
参考我的旧研究作为待复核种子，执行准确型号→真实图/商品找相似→深页→逐图→同店/主体补查。不要默认只查前两页或五页；逐路径记录新增量、预算和停止原因，保留断点。
Amazon 均价须来自符合本产品原始外形/功能要求的同类池，候选不低于均价；1688 搜索展示价和确认 SKU 采购价分开。先筛外形再评分，不以销量大或便宜放过错款。
分别报告相似商品数、具名供应商数和严格 ODM 工厂数；未知就明确未知，不把30个商品当30家工厂。不足时给出差额与已经尝试的补查。
交付中文Excel，基础九表加必要的分页/逐图/供应商台账，保留实际图片和可点击链接；用检索前冻结的 requirements.json 验证未偏离需求，并实际目视复核。销量榜与综合评分榜分开，不凑 TOP N。
```

```text
$cross-market-product-selection

你要执行的是一次“多目标产品”的跨市场选品任务，不是用一套外观或价格条件筛所有产品。

全局任务：
- 模式：[Amazon / 1688 / 联合]
- 市场与站点：[例如 Amazon 德国、法国、意大利、西班牙；1688 中国大陆]
- 销量口径：[例如近30天可追溯销量]
- 评价口径：[星级、评价数、变体合并规则]
- 交付：一个中文 Excel，固定九表；严格合格不足不凑数。

产品A：
- 目标产品ID：[A-001]
- 目标产品名称/用途：[...]
- 参考商品链接或附件：[...]
- 视觉对标模式：[普通单图 / 严格多视图]
- 必需视图：[视图1=整体主视图；视图2=关键结构或状态图]
- 外观必须特点：[外观1=…；外观2=…]
- 允许变化：[...]
- 外观排除项：[排除1=…；无则写“无”]
- 必须功能：[功能1=…；功能2=…]
- 可选功能：[...]
- 排除功能：[禁用功能1=…；无则写“无”]
- Amazon 目标售价/币种/允许偏差：[...]
- Amazon 目标站点：[例如 DE、FR、IT、ES，或欧洲综合]
- 1688 目标成本/币种/允许偏差：[...]
- 1688 采购数量档位：[...]
- 目标严格合格数量：[...]

产品B：
- 目标产品ID：[B-001]
- 目标产品名称/用途：[...]
- 参考商品链接或附件：[...]
- 视觉对标模式：[普通单图 / 严格多视图]
- 必需视图：[视图1=整体主视图；视图2=关键结构或状态图]
- 外观必须特点：[外观1=…；外观2=…]
- 允许变化：[...]
- 外观排除项：[排除1=…；无则写“无”]
- 必须功能：[功能1=…；功能2=…]
- 可选功能：[...]
- 排除功能：[禁用功能1=…；无则写“无”]
- Amazon 目标售价/币种/允许偏差：[...]
- Amazon 目标站点：[例如 DE、FR、IT、ES，或欧洲综合]
- 1688 目标成本/币种/允许偏差：[...]
- 1688 采购数量档位：[...]
- 目标严格合格数量：[...]

执行要求：
1. 必须先输出冻结合同：一行一个目标产品，展示目标产品ID、参考图、必需视图、外观/功能/排除编号、两侧价格与 Top-N。只询问会改变检索或资格判断的缺失信息；未确认的产品不得进入批量检索。
2. 必须按目标产品ID完全隔离参考图、检索词、均价样本、外观/功能证据、价格边界、去重、评分、排名和结果数量。不得复制上一个产品的证据或用同一组泛词通过多个产品。
3. 先检查参考图的真实外形和功能资料，不得仅根据型号名或用户简称推断。严格多视图产品的每个候选至少嵌入主图与关键结构/状态图，两图原始像素都不小于 240×240，并保留可单击原链接。
4. 外观逐项证据必须对每个“外观N/排除N”分别写：“候选可见事实=…；对标参考=…；关键差异=…”。标题、关键词、“整体相似”或跨行重复模板句不能通过。
5. Amazon 每个目标产品至少用 5 个位于其`Amazon目标站点`内、本体/外观/功能均合格的同类样本重算算术均价；`样本商品ID`和`跨站产品组ID`都必须分别去重，不能把同一商品改换组 ID 重复计数。候选严格价格下限=max(合格同类均价,目标售价×(1-允许偏差))，上限=目标售价×(1+允许偏差)。已知价格低于下限或高于上限时直接淘汰，不得放入待核验。
6. 1688 每个目标产品独立使用目标成本×(1±允许偏差)的上下限。已知价格越界时直接淘汰；严格候选必须同时绑定具体 SKU/规格、与目标合同一致的采购数量档位、MOQ、对应阶梯价、供应商主页、生产能力和 ODM/OEM/定制证据。阶梯价使用`数量=单价 币种/单位；...`格式；MOQ 不得高于目标采购数量，实际单价和币种必须等于该数量对应的档位报价。
7. 只对严格合格行在同一目标产品ID内按销量40%、价格40%、评价20%评分和排名。严格数量不足不凑数；给出每个目标产品的要求数、严格数、待核验数、淘汰数和限制。
8. 使用固定九表：任务说明、目标产品、价格基准、亚马逊候选、1688候选、货源匹配、严格结果、待核验、淘汰记录。所有业务行必须填写目标产品ID，图片嵌入 Excel，全部 URL 同时保留文本和可单击 hyperlink。
9. 交付前必须运行 Skill 自带的工作簿校验器并传入检索前独立保存的 requirements.json，不得从结果表倒生成需求基线；任何价格、外观证据、图片、身份、去重、评分、排名或表结构错误都不得作为正式结果交付。程序通过后仍须对照原始请求及实际图片复核。
10. 按每个目标产品的真实参考图/商品 ID 找相似、扩展深页、同店商品及供应商主体；保存逐页新增 ID、原始返回和逐图记录。第一页/第五页不是默认结束点，停止须有返回信号、增量停滞或确认预算依据，并保留断点。主体未知但图形有价值的商品保留为待核线索，不伪造工厂资格。
```

## 多 Agent 协同入口

协作模式：[单 Agent / 多 Agent]。需要独立并行协作时，可将下段附到上面的产品需求后；适用于一个或多个目标产品：

```text
请使用这个 Skill 内置的多 Agent 协同编排。
由主协调者读取原始需求，为各产品冻结独立基线；按目标产品、平台/站点和阶段拆分任务。
建立“多 Agent 协同运行清单”，实际调用可用子 Agent，登记真实执行者、依赖、预算份额、独占输出和完成条件。
商品发现、视觉/功能核验、市场数据、供应商/报价核验按需分工；独立任务并行，依赖上游的任务在验收后开始。
每个子 Agent 保存完整原始返回、结构化证据及断点；只有主协调者合并并写最终 Excel，按产品重算去重、均价、数量和排名。
安排未参与首次研究的独立红队复核，返工项修复后再验收。请按实际工具并发限制分批运行，不硬凑人数。
评论挖掘与差异化设计仅在我明确需要时启用。环境无法运行多个 Agent 时说明降级与限制，继续完成可做部分。
```

## 使用要点

- 目标产品越多，越要保持每个 ID 的证据、均价和排名相互独立。
- 如果用户只给型号没有参考图，先补图或可核验商品页，不使用模型常识自行补完外观合同。
- 已知价格越界是明确失败，不是“待核验”。待核验只用于价格、视图、功能或身份尚缺可靠证据且没有明确失败的情况。
