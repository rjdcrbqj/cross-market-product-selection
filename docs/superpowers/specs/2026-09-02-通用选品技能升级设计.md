# 通用选品技能升级设计

日期：2026-09-02
状态：已获得用户口头设计确认，等待书面设计复核

## 1. 背景与目标

现有 `cross-market-product-selection` 已能组织 Amazon、1688 和跨平台货源匹配，但真实使用暴露出四类通用问题：

1. 任务专属的外观与功能条件没有被固化成可执行硬门槛；
2. 标题关键词可能被误当成主图外观证据；
3. 不同站点的重复商品、原始搜索噪声和证据不足的供应商可能混入最终结果；
4. Excel 使用英文列名、只保留图片链接或缺少稳定的中文交付规范。

本次升级把 Skill 设计为通用品类引擎。吹风机、保温杯、工具、家具等都使用同一套流程，产品专属规则只存在于当次《选品任务书》或可选品类配置中，不写死在核心 Skill。

## 2. 设计原则

- **通用核心，任务专属门槛。** 核心只规定如何确认、检索、核验、评分和交付，不内置某一具体产品的外形结论。
- **先确认，后批量检索。** 外观、功能、目标价格和排除项会改变筛选结果时，必须先向用户确认。
- **先硬门槛，后评分。** 外观、功能、产品身份、价格范围或供应商资质不合格时，销量再高也不能进入排名。
- **主图是外观最终证据。** 标题、关键词、搜索缩略图或生成图片不能代替具体商品与变体的实际主图。
- **不凑数量。** 严格合格数量不足时如实交付较少结果。
- **中文优先。** Skill 内容、Excel 工作表、表头、状态、说明、结论和 GitHub 使用文档默认使用中文。
- **证据可追溯。** 每个关键事实保留来源、获取时间、商品身份、变体和核验说明。

## 3. 总体架构

### 3.1 通用核心

核心 Skill 负责以下稳定流程：

1. 生成并确认选品任务书；
2. 建立多路径检索矩阵；
3. 获取、规范化并去重候选；
4. 核验商品身份、外观、功能、价格和证据；
5. 将候选划分为“严格合格、待核验、已淘汰”；
6. 对严格合格候选按统一公式评分；
7. 生成中文 Excel，嵌入图片并完成自动校验。

### 3.2 当次选品任务书

每次任务动态生成，不沿用其他产品的具体外形要求。任务书至少包含：

| 分类 | 必填内容 |
| --- | --- |
| 任务范围 | Amazon、1688 或联合模式；国家、站点、类目和目标数量 |
| 参考产品 | 商品名称、链接、商品 ID、参考图片或用户提供文件 |
| 外观特点 | 必须出现的结构、形状、比例、颜色、材质、折叠或组合方式、关键识别点 |
| 外观排除项 | 明确不接受的形态、结构、套装、颜色或变体 |
| 功能特点 | 必须功能、可选功能、排除功能及可接受证据 |
| 价格目标 | 目标售价或目标采购成本、币种、含税口径、采购数量或起订量、允许偏差 |
| 数据口径 | 销量来源、统计周期、评价口径、跨站点合并或分站排名方式 |
| 缺失处理 | 缺失时留空、进入待核验或停止该路径 |

用户只给出商品名称但未提供足以确认外观的图片、链接或结构描述时，可以先做少量探索，但不得直接生成最终“严格合格”清单。Skill 应先展示中文《目标产品确认表》，让用户确认或纠正。

### 3.3 可选品类配置

未来可以增加可选的品类配置，存放常见字段、检索同义词和合规提示。配置只提供起点，不能替代当次用户确认，也不能把一次失败案例升级为所有品类的固定规则。

## 4. 外观、功能与价格检索

### 4.1 外观核验

外观要求拆为“必须特点、允许变化、明确排除”三组。每个最终候选必须记录：

- 实际商品主图及主图链接；
- 主图对应的商品 ID、站点和变体；
- 命中的必须特点；
- 观察到的差异；
- 外观结论与具体理由。

若主图为空、无法确认变体、图片是广告拼图或图片与商品身份冲突，外观状态只能是“待核验”或“不通过”。

### 4.2 功能核验

功能要求拆为“必须、可选、排除”。标题可以用于发现候选，但最终功能结论必须来自可靠详情页字段、规格表、说明书或同等级证据。只有必须功能全部通过的候选才能进入严格结果。

### 4.3 价格相似性

- Amazon 商品与目标销售价格比较；
- 1688 商品与目标采购成本比较；
- 1688 必须使用与目标采购数量相符的阶梯价格；
- 不同币种必须先按已记录的汇率和时间转换，不能直接比较原始数字；
- 用户设定的允许价格范围属于硬门槛，范围内再计算价格相似分。

价格相似分采用双向接近原则，低太多或高太多都会扣分：

```text
价格相似分 = MAX(0, 100 × (1 − |实际价格 − 目标价格| ÷ 目标价格))
```

例如目标价格为 150：150 得 100 分，135 和 165 均得 90 分，120 和 180 均得 80 分。

## 5. 检索与去重

### 5.1 Amazon

根据任务书组合使用关键词、同义词、功能词、外形词、竞品、类目、品牌和详情页路径。Sorftime 可用时优先使用；不可用或不完整时，在用户确认付费调用范围后使用 SerpApi 补充 Amazon 数据。

同一国家站点内按“站点 + ASIN + 变体”规范化。若用户要求欧洲综合产品榜，同一产品在多个站点的观测保留在明细中，但最终产品榜不得重复占位；若用户要求分国家榜，则各站点分别排名并明确标签。

### 5.2 1688

组合使用关键词搜索、以图搜款、相似商品、同店商品和供应商主页路径。商品按商品 ID 去重，供应商榜按可靠供应商主体去重。

“30 家工厂”必须是 30 个经过供应商主页或同等级证据核验的主体，不能把 30 个商品链接直接等同于 30 家 ODM 工厂。严格供应商至少需要：

- 供应商主页与主体名称；
- 制造商、工厂或生产能力证据；
- ODM、OEM、定制或打样能力证据；
- 与目标商品相关的合格商品链接；
- 起订量、阶梯价格和获取时间。

普通店铺标签、店名中的“厂”字或一件代发不能单独证明 ODM 工厂身份。

## 6. 评分与排序

评分只用于已经通过全部硬门槛且三个评分字段都有可靠证据的候选。

### 6.1 销量标准分

默认在同一市场、同一来源、同一统计周期的严格候选内进行 0–100 最小最大标准化：

```text
销量标准分 = 100 × (当前销量 − 最低销量) ÷ (最高销量 − 最低销量)
```

若最高销量等于最低销量，所有可比候选的销量标准分均为 100。不同站点、不同周期或不同来源的销量不得在未说明转换规则时直接混排。

### 6.2 评价标准分

五星制平台默认使用：

```text
评价标准分 = 商品星级 ÷ 5 × 100
```

评价数量作为可信度提示与同分排序依据，不改变用户确定的 4:4:2 权重。任务书可以设定最低评价数量硬门槛。

### 6.3 总评分

```text
总评分 = 销量标准分 × 40% + 价格相似分 × 40% + 评价标准分 × 20%
```

结果按总评分从高到低排序。同分时依次比较销量标准分、评价数量、价格相似分。默认情况下，缺少销量、价格或评价证据的行不计算总评分并进入“待核验”；只有用户事先明确批准其他缺失处理方式时才可改变这一规则。

1688 商品排名使用同一结构：可比周期销量、与目标采购成本的价格相似度、可靠的商品或服务评价。供应商资质仍是独立硬门槛，不能被评分抵消。

## 7. 中文 Excel 交付规范

### 7.1 中文优先

默认工作表名称：

- `任务说明`
- `亚马逊候选`
- `1688候选`
- `货源匹配`
- `严格结果`
- `待核验`
- `淘汰记录`

表头、状态、门槛结论、排序结论、筛选原因和备注均使用中文。保留无法合理翻译的技术标识，如 `ASIN`、`SKU`、`URL`、`API`、`FBA`、`Sorftime` 和 `SerpApi`；首次出现时提供中文说明。

统一状态值：

- `严格合格`
- `待核验`
- `已淘汰`

统一门槛值：

- `通过`
- `待核验`
- `不通过`

### 7.2 表头与任务说明

`任务说明` 使用中文记录目标、参考产品、外观特点、功能特点、排除项、价格口径、评分公式、数据范围、获取时间、缺失处理和决策变更。

数据表头至少包含适用的以下字段：

`状态`、`门槛原因`、`商品图片`、`主图链接`、`商品ID`、`站点`、`品牌`、`商品标题`、`商品链接`、`外观匹配说明`、`功能匹配说明`、`目标价格`、`实际价格`、`价格偏差`、`销量`、`评价星级`、`评价数量`、`销量得分`、`价格得分`、`评价得分`、`总评分`、`排名`、`证据来源`、`获取时间`。

### 7.3 图片嵌入

每个商品行必须在 `商品图片` 列嵌入与商品 ID 和变体一致的实际主图，同时保留 `主图链接` 用于追溯。

- 图片保持原始比例，不拉伸；
- 统一图片框和行高，图片随单元格移动；
- 每行只放对应商品主图，不使用搜索广告、相关商品图或生成图片；
- 需要外观硬门槛但图片无法下载或嵌入时，该行不得进入严格结果；
- 对所有工作表使用可筛选 Excel 表格、冻结表头、中文字体和可读列宽。

## 8. 自动校验

升级增加确定性的工作簿校验脚本或等价检查流程。导出前至少验证：

1. 必需工作表和中文表头存在；
2. 严格结果没有重复的最终产品或供应商身份；
3. 需要外观核验的严格行同时具有嵌入图片、主图链接和外观说明；
4. 外观、功能和供应商硬门槛全部为“通过”；
5. 三项评分输入存在且公式权重为 40%、40%、20%；
6. 总评分从高到低排序，排名连续且未凑数；
7. 缺失值没有被无依据地写成 0；
8. 1688 严格供应商具有供应商主页和 ODM/生产能力证据；
9. 来源链接、商品身份和获取时间完整；
10. 工作簿能够打开并经过视觉检查，图片没有错行、遮挡或拉伸。

任何一项会改变最终结论的检查失败时，停止交付并修复；无法修复时将相关行降为待核验并披露原因。

## 9. Skill 与仓库中文化

- `SKILL.md` 正文改为中文，保留规范要求的固定文件名和英文 Skill 名称；
- 参考文件正文和可安全重命名的参考文件使用中文；
- `agents/openai.yaml` 保持中文展示名、说明和默认提示词；
- `README.md` 更新中文安装、调用、输入准备、评分公式和 Excel 输出说明；
- 技术品牌、API 参数、文件格式和固定标识保留原文并在首次出现时解释。

默认输出中文；只有使用者明确要求其他语言时才切换。

## 10. 兼容性与版本

- 继续使用 `cross-market-product-selection` 名称和现有安装路径；
- 保留 Amazon、1688 和联合三种模式；
- 现有英文表头模板升级为中文表头，旧工作簿仍可作为用户输入读取，但新输出必须遵循中文规范；
- 此次为行为和交付结构升级，发布时使用新的语义化版本号，并保留 `v1.0.0` 标签供稳定复现；
- GitHub 发布说明列出评分公式、中文化、嵌图、外观/功能确认和供应商证据门槛的变化。

## 11. 验证场景

实现完成后至少验证以下场景：

1. **吹风机外观场景：** 任务书明确一种参考结构，传统不同结构即使销量高也不能进入严格结果；该规则来自任务书而非核心 Skill。
2. **不同品类场景：** 使用保温杯或其他产品验证核心流程无需修改即可工作。
3. **缺少参考图：** 请求外观相似但证据不足时，Skill 先要求确认，不直接输出严格 Top-N。
4. **主图缺失：** 主图为空或未嵌入的候选不能标为严格合格。
5. **跨站点重复：** 欧洲综合榜中同一产品不会重复占位，分站榜仍保留各站观测。
6. **评分计算：** 使用已知样例验证销量、价格、评价和总评分公式及降序排列。
7. **价格对称性：** 目标价格上下相同偏差得到相同价格分。
8. **供应商证据：** 只有商品链接或店名带“厂”字时不能判定为严格 ODM 工厂。
9. **中文与嵌图：** 新模板的工作表、表头、状态和说明为中文，每个严格商品行都有嵌入主图和主图链接。
