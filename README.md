# 跨市场选品与货源匹配 Skill

一个面向 Codex 的证据化选品工作流，支持：

- Amazon 市场机会与竞品分析；
- 1688 商品及供应商筛选；
- Amazon 需求与 1688 货源联合匹配；
- 按硬门槛、证据质量和评分规则生成可复核的 Excel 选品数据库。

> 当前稳定版本：[`v1.0.0`](https://github.com/rjdcrbqj/cross-market-product-selection/releases/tag/v1.0.0)

这个链接固定安装 `v1.0.0`，适合希望结果稳定、可重复的用户。

安装完成后，可在下一条消息或新任务中调用。如果 Skill 没有出现在列表中，请重启 Codex。

Codex 官方也支持使用 `$skill-installer` 从其他代码仓库安装 Skill，并使用 `$技能名` 显式调用。参见 [OpenAI Skill 官方说明](https://learn.chatgpt.com/zh-Hans/docs/build-skills)。

### 2. 调用 Skill

推荐在提示词开头显式写出 Skill 名称：

```text
$cross-market-product-selection
```

最简示例：

```text
$cross-market-product-selection

```

Skill 也可以根据任务描述自动触发，但显式调用更容易确认使用了正确的工作流。

## 三种工作模式

### Amazon 模式

适合分析 Amazon 市场机会、竞品、价格、评分、评论、外观和产品差异。

可复制示例：

```text
$cross-market-product-selection

模式：Amazon。
目标市场：Amazon 美国站。
品类：便携榨汁杯。
目标数量：最多 20 个严格候选，不足 20 个不要凑数。

硬门槛：
1. 必须是完整产品，不得是杯盖、刀头、电池等配件；
2. 容量为 12–20 oz；
3. 主图必须显示便携式一体结构；
4. 商品页面和 ASIN 身份必须一致。

排除项：替换零件、组合配件包、传统台式搅拌机。

评分权重：
- 评分数量 25；
- 星级评分 15；
- 价格带匹配 20；
- 产品差异化 20；
- 竞争强度 20。

缺失数据留空；硬门槛证据缺失的产品放入“待核验”，不得进入严格排名。
输出中文 Excel，并保留商品链接、证据、原始数据、评分公式和淘汰原因。
```

### 1688 模式

适合寻找商品、工厂和供应商，并比较价格、起订量、定制能力、交期及供应证据。

可复制示例：

```text
$cross-market-product-selection

模式：1688。
目标：为 30 oz 圆柱形保温杯寻找可定制货源。
目标数量：最多 15 个严格候选，不足时不要凑数。

硬门槛：
1. 商品详情页明确说明 304 不锈钢；
2. 起订量不超过 100 个；
3. 支持 Logo 定制；
4. 实际商品图外形符合圆柱形参考款；
5. 必须是完整杯体，不得是杯盖、吸管或其他配件。

评分权重：单价 25、起订量 20、供应商证据 20、定制能力 20、交期 15。
缺失字段留空，无法核实硬门槛的候选放入“待核验”。
输出中文 Excel，并记录商品链接、供应商链接和每个字段的证据来源。
```

### 联合模式

适合先识别 Amazon 需求，再寻找并匹配 1688 货源。

可复制示例：

```text
$cross-market-product-selection

模式：Amazon 美国站 + 1688 联合选品。
目标：寻找有市场机会、同时具备可落地货源的差异化保温杯。
参考：我提供的产品图片和 Amazon 商品链接。
目标数量：最多 10 组严格匹配，不足 10 组不要凑数。

Amazon 硬门槛：完整产品、24–32 oz、圆柱形、防漏杯盖、主图符合参考外形。
1688 硬门槛：304 不锈钢、起订量不超过 100、支持定制、商品图外形匹配。
排除：替换杯盖、吸管包、带手柄旅行杯和无关套装。

请分别计算：
1. Amazon 市场机会分；
2. 1688 供应能力分；
3. Amazon 与 1688 的匹配质量分。

缺失数据留空，不允许猜测。
输出完整七页 Excel，保留严格结果、待核验和淘汰记录。
```

## 使用前最好提供的信息

信息越完整，正式检索前的确认轮次越少。Skill 会重点确认：

| 信息 | 示例 |
| --- | --- |
| 工作模式 | Amazon、1688 或联合模式 |
| 产品和用途 | 便携榨汁杯、宠物饮水机、保温杯 |
| 市场或地区 | Amazon 美国站、德国站；1688 中国货源 |
| 参考资料 | 商品链接、ASIN、1688 商品 ID、图片、品牌或外形参考 |
| 目标数量 | 最多 20 个严格候选，允许少于 20 个 |
| 硬门槛 | 材质、尺寸、外形、颜色、价格、起订量、认证等 |
| 排除项 | 配件、替换零件、套装、指定品牌或外形 |
| 评分规则 | 指标、越高或越低越好、权重；全部权重合计 100 |
| 缺失值规则 | 留空、待核验、排除，或用户明确批准的评分处理方式 |
| 输出要求 | Excel、语言、币种、单位和保存位置 |
| 检索预算 | 页面深度、时间范围，以及 SerpApi 最大调用次数 |

如果这些信息不完整，Skill 会只询问会影响检索、合格判断、评分或交付结果的问题。

## 数据来源与 SerpApi

### 已配置 Sorftime

优先使用用户已经配置并授权的 Sorftime 数据能力。Skill 仍会核对具体商品身份、变体、主图和关键字段证据，不会把单个搜索结果页当作完整市场。

### 没有配置 Sorftime

Amazon 调研可以使用 [SerpApi](https://serpapi.com/) 作为备用数据来源。

使用前请：

1. 在 SerpApi 创建账户并取得 API Key；
2. 将 Key 安全配置到运行 Codex 的环境变量 `SERPAPI_KEY` 中；
3. 不要把 API Key 粘贴到聊天、Excel、公开日志或 GitHub；
4. 重启 Codex，使新环境变量生效；
5. 在正式批量调用前确认站点、关键词、页数、详情深度和最大调用次数。

调用示例：

```text
$cross-market-product-selection

没有配置 Sorftime，允许使用 SerpApi 搜索 Amazon 美国站。
先用最小样本验证关键词和返回字段；本次最多调用 30 次。
开始付费批量查询前，请先向我确认预计范围。
```

注意：

- SerpApi 可能产生费用，实际套餐、额度和计费以 SerpApi 账户为准；
- SerpApi 只作为 Amazon 侧的备用来源；
- SerpApi 不能作为 1688 商品详情来源；
- 1688 侧需要 Sorftime、已授权浏览器访问、用户提供的文件或其他可靠来源。

## Skill 的工作方式

收到完整需求后，Skill 会按照以下顺序处理：

1. 固定选品任务书、硬门槛、排除项、评分权重和检索预算；
2. 建立关键词、同义词、外形词、功能词及发现路径组成的检索矩阵；
3. 收集候选并按 ASIN、1688 商品 ID 或规范链接去重；
4. 先核验产品身份、硬门槛和实际主图；
5. 将候选分为“严格合格”“待核验”和“已淘汰”；
6. 只对严格合格候选评分和排名；
7. 生成带来源链接、证据、公式和审计记录的 Excel。

## 重要规则

- **硬门槛先于评分。** 未通过硬门槛的产品不会因为销量或评分高而进入结果。
- **不凑 Top-N。** 用户要求 20 个但只有 8 个严格合格时，只输出 8 个。
- **主图是外观类要求的最终门槛。** 标题关键词不能代替真实商品图片。
- **缺失数据保持空白。** 不用 `0`、估算值、搜索摘要或无法解释的数字填充事实字段。
- **严格、待核验和淘汰分开。** 缺少必要证据的候选不会被冒充为严格结果。
- **结果可追溯。** 关键字段保留来源链接、获取时间、证据状态和冲突说明。
- **密钥不外泄。** API Key 不进入提示词、输出文件、日志或仓库。

## Excel 输出

默认从内置的 `通用选品数据库模板.xlsx` 开始生成。标准工作簿包含七个工作表：

| 工作表 | 用途 |
| --- | --- |
| `任务说明` | 已确认的需求、决策记录、权重、检索范围、来源顺序和限制 |
| `Amazon候选` | Amazon 候选、证据、门槛状态、原始指标和市场机会分 |
| `1688候选` | 1688 商品及供应商、证据、门槛状态和供应能力分 |
| `货源匹配` | Amazon 与 1688 配对记录、维度证据和匹配质量分 |
| `严格结果` | 仅包含通过全部硬门槛的排序结果 |
| `待核验` | 缺少必要证据的候选及下一步核验动作 |
| `淘汰记录` | 已确认未通过硬门槛的原因和证据 |

单一模式只填充相关页面；联合模式使用全部七页。表格会尽量保留筛选、公式、可点击链接、原始值、标准化分数和审核字段。

## 常见问题

### 为什么结果数量少于我要求的数量？

因为 Skill 不会为了补足数量而放宽门槛。结果不足时，会说明哪些硬门槛导致候选减少，以及哪些检索路径未完成或不可用。

### 为什么有些商品在“待核验”中？

它们尚未发现明确失败证据，但至少一个必要硬门槛缺少可靠证据。补齐证据后才能进入严格结果。

### 为什么 SerpApi 不能直接查 1688？

本 Skill 将 SerpApi 限定为 Amazon 侧备用来源。1688 商品、供应商、起订量和定制能力需要使用能访问对应详情页的可靠来源。

### 如何更新到新版本？

需要稳定复现时，继续安装带版本号的链接。希望使用最新内容时，安装 `main` 链接。升级前建议先阅读 [Releases](https://github.com/rjdcrbqj/cross-market-product-selection/releases) 中的变更说明。
